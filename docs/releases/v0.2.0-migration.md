# Migrating from GoldenPath v0.1.0 to v0.2.0

**Production validation: NOT CLAIMED.** This migration guide describes repository/reference and supported ephemeral-runtime behavior only.

## Compatibility summary

v0.2.0 is additive for the public reference repository. Existing Terraform modules, GitOps examples, policy bundles, service templates, and v0.1.0 documentation remain usable.

The main behavioral change is that runtime assurance is now a first-class contract rather than a future validation requirement.

## New requirements for the supported Runtime Lab

The full v0.2.0 path requires Git, Python 3, OpenSSL with Ed25519 support, Docker, kind, kubectl, Helm, Go, Copier, and the repository's locked Python dependencies.

Run:

```bash
python3 goldenpath doctor --scope all
```

before the Runtime Lab.

## Evidence changes

v0.1.0 repository evidence is not automatically upgraded into runtime evidence. A v0.2.0 runtime claim requires a fresh Runtime Lab execution and a receipt bound to the exact source, artifact, desired state, policy, and runtime identities.

Historical PASS remains historical. Drift or recovery requires current observations and, for a recovered healthy state, a new receipt.

## CLI adoption

```bash
python3 goldenpath validate --artifact-dir /tmp/goldenpath-runtime-lab
python3 goldenpath lab up --artifact-dir /tmp/goldenpath-runtime-lab --lab-id local-v020
python3 goldenpath assure --artifact-dir /tmp/goldenpath-runtime-lab
python3 goldenpath verify --artifact-dir /tmp/goldenpath-runtime-lab
python3 goldenpath evidence show --artifact-dir /tmp/goldenpath-runtime-lab
```

## No production migration implied

Moving to v0.2.0 does not certify or migrate a production platform. Production adoption still requires organization-specific validation of real clusters, identity, secrets, networking, registries, observability, approvals, recovery, and operational ownership.
