# GoldenPath v0.2.0 — Runtime Evidence & Autonomous Assurance

GoldenPath v0.2.0 extends the v0.1.0 repository/reference baseline with a reproducible ephemeral Kubernetes Runtime Lab and identity-bound runtime assurance.

**Evidence boundary:** repository/reference evidence and supported ephemeral-runtime evidence.  
**Production validation: NOT CLAIMED.**

## What is new

- Versioned runtime assurance contracts and explicit repository/runtime/production claim tiers.
- Reproducible kind-based Runtime Lab with Argo CD reconciliation, admission denial, immutable digest observation, cleanup, and residue checks.
- Signed Ed25519 runtime assurance receipts bound to the exact source revision, artifact digest, desired-state revision, assurance plan, policy bundle, and runtime identity.
- Independent receipt verification with tamper, replay, stale-evidence, signature, and identity-mismatch rejection.
- Continuous assurance semantics that distinguish historical PASS from current runtime state and require new evidence after recovery.
- Official `goldenpath` CLI for doctor, plan, validate, lab, assure, verify, and evidence reporting.
- Human-readable assurance reports and machine-readable scorecards without invented aggregate percentages.
- P5 exact-candidate qualification that binds repository validation, Runtime Lab facts, signed receipt, independent verification, current-state assurance, scorecard, and release documentation.

## Exact candidate qualification

The P5 Runtime Lab workflow checks out the exact candidate SHA and runs:

```text
validate -> lab up -> assure -> verify -> continuous assurance -> evidence show -> qualify release candidate
```

The final `release-candidate-evidence.json` is emitted only when all required evidence is present, current, internally consistent, and bound to the exact candidate revision.

## Supply-chain boundary

GoldenPath's generated Go delivery path has repository/reference controls for registry-attached SPDX SBOMs, SLSA provenance, digest-bound keyless Cosign signing, and identity-constrained verification.

The v0.2.0 GoldenPath repository release itself is a source/tag release plus an Actions-retained evidence bundle. P5 does not invent an SBOM, provenance statement, or signature for GitHub-generated source archives. Those source-archive claims remain **NOT CLAIMED** unless a future release pipeline produces and verifies them explicitly.

## Compatibility

v0.2.0 preserves the v0.1.0 repository structure and adds Python/Bash assurance tooling, schemas, Runtime Lab resources, and CLI behavior. See [migration notes](v0.2.0-migration.md).

## Verification boundary

A successful v0.2.0 qualification proves that the supported ephemeral Runtime Lab executed and produced valid runtime evidence for the exact candidate. It does not prove a real organization's production clusters, cloud identities, registries, DNS, secrets, observability, approvals, incident controls, or operational ownership.
