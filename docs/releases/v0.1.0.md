# GoldenPath v0.1.0 — Public Reference Baseline

GoldenPath v0.1.0 establishes the first tagged public baseline for the repository.

This release is intentionally a `0.x` baseline. It provides a stable, inspectable reference point for the implemented contracts and documentation without implying production adoption or a 1.0 compatibility commitment.

## Highlights

- Evidence-driven Golden Path reference architecture for Kubernetes platform engineering.
- Deterministic R0-R4 risk-adaptive assurance with explicit autonomy modes and required controls.
- Versioned `goldenpath.evidence/v1` fail-closed evidence semantics.
- Architecture as Code and authoritative policy, architecture, and desired-state input binding.
- Root CI covering repository structure, documentation, Terraform, GitOps/policy contracts, service templates, English-only content, and full reachable-history secret scanning.
- Argo CD as the authoritative Kubernetes reconciler for the reference platform layer.
- Multi-provider Terraform policy reference coverage for AWS, Azure, and Google Cloud.
- Go paved-road template with immutable image identity, SBOM, SLSA provenance, and keyless Cosign signing.
- Digest-bound GitOps promotion that verifies the exact image signature and signed SLSA provenance before desired-state mutation.
- Envoy Gateway / Gateway API reference baseline and maintained platform add-on definitions.
- Public visual architecture and a zero-cloud assurance demo.

## Try the assurance model

From a clean clone:

```bash
git clone https://github.com/lloga29/goldenPath.git
cd goldenPath
./scripts/demo.sh
```

The demo requires only Bash and Python 3. It derives an assurance plan, validates evidence bound to that plan, and proves that incomplete required-gate evidence is rejected.

## Supply-chain path

The implemented Go reference path demonstrates:

1. build and test validation;
2. immutable container image identity;
3. SBOM attestation;
4. SLSA provenance;
5. keyless Cosign signing;
6. identity-bound verification of the exact digest;
7. GitOps promotion by digest only;
8. signature and signed-provenance verification before desired-state mutation.

These controls are repository/reference implementation evidence. A rendered workflow or successful fixture does not prove that a specific external registry or runtime environment is operational.

## Evidence boundary

This release certifies a **repository/reference baseline**.

It does not, by itself, provide runtime evidence or production validation for:

- cloud accounts or infrastructure deployments;
- container registries or transparency services;
- Argo CD reconciliation against a live destination;
- Kubernetes clusters or workload health;
- DNS, certificates, external secrets, or network traffic;
- production approvals, SLOs, rollback exercises, backups, or incident procedures.

Runtime and production claims require separate evidence from real systems and exact execution contexts.
