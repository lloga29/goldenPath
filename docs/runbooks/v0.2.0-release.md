# GoldenPath v0.2.0 Release Runbook

This runbook publishes v0.2.0 only after the exact candidate passes every required gate.

**Production validation: NOT CLAIMED.**

## Preconditions

1. Issues #92 through #97 are implemented by reviewed changes.
2. The exact candidate SHA has green repository validation and Runtime Lab checks.
3. P5 produced `release-candidate-evidence.json` for that exact SHA.
4. The candidate receipt verifies independently.
5. Continuous assurance is `VERIFIED_HEALTHY` or `RECOVERED_REVERIFIED`.
6. The platform scorecard reports repository evidence `VERIFIED`, runtime evidence `VERIFIED`, and production `NOT_CLAIMED`.
7. Required negative tests are green.
8. Public documentation contains no unsupported production-validation claim.
9. `main` has not advanced incompatibly since candidate validation.

## Release procedure

1. Re-read the exact candidate SHA from the PR head.
2. Confirm all required checks are complete and successful for that SHA.
3. Confirm the PR is mergeable and no incompatible `main` drift exists.
4. Squash-merge using the repository's configured merge method.
5. Revalidate the resulting `main` commit with root repository validation and Runtime Lab.
6. Create immutable tag `v0.2.0` on the verified release commit.
7. Create the GitHub release from `docs/releases/v0.2.0.md`.
8. Record the release commit and workflow run IDs in the release description or evidence record.
9. Run the post-release checklist.

## Abort conditions

Do not publish when any required check is red, pending, cancelled, or silently skipped outside an explicit allowed contract; when evidence identities differ; when the receipt or verification binding fails; when current runtime state is degraded/failed/needs-human; or when documentation overstates the evidence tier.

A failed release attempt does not authorize weakening the gate. Fix the cause and produce fresh evidence.
