Why GoldenPath is different

The paved road is only trusted when its evidence is trustworthy.

01

Risk-adaptive assurance

R0-R4 controls change according to deterministic Architecture as Code and change inputs rather than a one-size-fits-all pipeline.

02

Evidence-bound controls

Policy, architecture, source, desired state, and assurance evidence are bound to authoritative inputs instead of self-declared status.

03

Supply-chain trust

The Go reference path uses immutable digests, SBOM attestations, SLSA provenance, and identity-bound keyless signatures.

04

Governed GitOps

Promotion is reviewable, digest-only, and verifies trusted release evidence before mutating desired state.

Evidence boundary

Green is not the same as proven in production.

Repository / referenceCode, contracts, fixtures, renders, validation
→
RuntimeReal registry, cluster, reconciliation, workload proof
→
Production validationOperational approvals, SLOs, recovery, live controls

GoldenPath deliberately refuses to present repository validation as proof that a real cloud account, registry, DNS zone, secret backend, Kubernetes cluster, or production workload is operational.
